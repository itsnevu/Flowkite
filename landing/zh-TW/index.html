一個會先問過你的瀏覽器代理。

用日常語言描述任務，Flowkite 就在你自己的瀏覽器裡完成它，Planner 想好做法，Navigator 負責點擊和輸入，你在側邊面板看著整個過程發生。它在碰任何頁面之前先給你看計畫，遇到不可逆的事情會停下來問，資料直接送往你選擇的模型供應商、用的是你自己的金鑰。中間沒有任何 Flowkite 伺服器。

試著這樣問： 「在三家商店裡找出最便宜的 AeroPress 濾紙，然後下單。」

看它運作

「先問過你」長這個樣子。

一項任務，在側邊面板重播。Planner 提出計畫後等待，唯讀分頁負責查資料，唯一會花錢的那一步，在發生之前停下來等你點頭。

它實際做的事

代理最有意思的部分，是它在哪裡停下來。

多數瀏覽器代理跟你要已登入的工作階段，然後就開始動手。Flowkite 反著造：下面每一項，都是它把控制權交還給你、或拒絕花掉你沒同意的東西的地方。

  • 先看計畫，之後可復原

    代理在碰任何頁面之前，先把計畫寫出來等你。你核准它才跑；你拒絕，就什麼都沒發生。

    復原會回退最後一步，頁面退回去，而且代理忘掉那一步，於是它從還原後的狀態重新規劃，而不是疊在你否決的東西上面。

  • 敏感操作要你點頭

    購買、刪除、送出表單、下載檔案、在密碼欄輸入，全都會先停下來問你。

    這個檢查讀的是代理實際選中的 DOM 元素，它的標籤、型別、aria-label，而不是模型自認為在做什麼的描述。

  • 留在你裝置上的記憶

    偏好講一次，往後的工作階段都記得。記憶存在 chrome.storage.local，絕不會上傳到 Flowkite、永不同步。啟用記憶後，與該網站相符的記憶會進入送往你自己的 LLM 供應商的提示中。

    設定頁列出每一條存下的事實，旁邊就是刪除鍵，還有一個開關能整個關掉。

  • 平行分頁查資料

    彼此獨立的查詢，同一件商品在三家店，同時進行，各自在背景分頁裡跑，最後合併成一個答案。

    這些分頁從構造上就是唯讀的：交給它們的動作集合裡沒有點擊、沒有輸入、沒有送出。 你唯一無法介入的地方，正是什麼都動不了的地方。

  • 混合路由，更省 token

    指定一個可選的便宜模型，例行的導覽步驟就交給它，思考交給你的好模型。

    不例行的都會升級處理：要收拾的失敗、資訊密集的頁面、需要看截圖推理的步驟、新計畫的第一步。

  • 對不可信文字的防護欄

    頁面內容會包上明確的分隔符、先掃描再交給模型，網頁上的文字沒辦法偽裝成給代理的指令。

    已知的提示注入與任務挾持模式會被剝除，敏感字串在送出時被攔下。

  • 不用停下來也能糾正它

    以前看著它在第三步走錯方向，你只有一個按鈕可按：停止，然後失去它已經整理好的一切。現在你只要打字就好。

    修正會保留計畫已完成的進度，只覆蓋方向。它在步驟交界處生效，絕不會插進一個已經送出的模型呼叫底下，而且計畫會重新產生，讓舊路線無法和你的新指示互相牴觸。

  • 把檔案交給它上傳

    附上履歷、發票或照片，代理就能把它放進頁面的上傳欄位，包括那些把真正的 input 藏在別處、只露出美化按鈕的版型。

    檔案內容存在 session storage，Chrome 關閉就消失，而且永遠不會進入提示詞。每一次上傳都會先問你：這個動作一執行，檔案就離開你的電腦。

  • 盯著一個頁面，沒變化就不出聲

    每天的任務可以照排程執行，不需要有人看著。打開監看之後，它會把這次收集到的資料和上一次比對，只有真的有變化才通知你。

    價格變動會被讀成一列有變化，而不是一刪一增。純文字的回答一律不比對，因為模型每天早上都會用不同的說法寫同一件事，那樣等於每天都在打擾你。

運作方式

兩個代理，一個瀏覽器，零伺服器。

Flowkite 把工作拆成兩個角色：一個決定做什麼，另一個動手做。全部都在你電腦上的擴充功能 service worker 裡執行，唯一出去的東西，是發給你設定的模型供應商的請求。

  1. 1

    Planner

    讀你的任務、想好做法，哪些網站、什麼順序、「完成」長什麼樣子。當頁面跟所有人預期的都不一樣時，它會重新規劃。

    由它決定任務何時結束。必要角色。

  2. 2

    Navigator

    在頁面裡做實際的工作：讀 DOM、點擊、輸入、捲動、導覽。跨網域 iframe 也讀得到，所以內嵌的結帳和登入元件對它不是隱形的。

    頁面在步驟中途重新渲染的話，動作會對新狀態重試。例行步驟可以交給你指定的便宜模型；難的留給好模型。

計畫閘門擋在兩個代理前面。每個任務的第一份計畫都會呈給你、等你核准，而且只有第一份，所以任務中途的重新規劃不會一直煩你。開始跑之後，復原就是逃生口：它把頁面退回去、把那一步從代理的 歷史裡刪掉，下一份計畫蓋在你留下的狀態上，而不是你否決的那個。

  2. 2 加入 API 金鑰並指派模型

    打開側邊面板，點設定圖示，貼上任一支援供應商的金鑰，然後分別給 Planner 和 Navigator 各一個模型。若想把例行步驟從昂貴模型分流出去，再加一個便宜的 Fast 模型。

想自己手動安裝？

下載組建後自行載入，檔案和商店提供的完全一樣。代價是 Chrome 不會替你更新：有新版時要再下載一次並替換資料夾。

  1. 下載 flowkite.zip 並解壓縮。請放在不會誤刪的位置，因為 Chrome 會直接從那裡載入。

  2. 把這段貼到網址列。這不是網頁能替你開啟的連結。

    chrome://extensions/

  3. 在右上角開啟開發人員模式。否則 Chrome 不會顯示「載入未封裝項目」按鈕。

  4. 點載入未封裝項目，選解壓縮後的資料夾本身，不是裡面的檔案。接著從上面的步驟 2 繼續。

直球回答

常見問題，老實回答。

它是免費的嗎？

擴充功能免費下載，沒有付費方案、沒有試用期、不用帳號。要花錢的是模型：你帶自己的 API 金鑰，供應商按代理的用量直接向你收費。透過 Ollama 跑本機模型的話，連這筆錢也歸零。

我的 API 金鑰會去哪裡？

存進你電腦上的 chrome.storage.local，僅此而已。請求從你的瀏覽器直達你設定的供應商。 Flowkite 沒有後端可以代理它們，所以不存在任何一台能看到金鑰的我方伺服器。解除安裝擴充功能，金鑰也跟著消失。

支援本機模型嗎？

支援，Ollama 有直接支援，任何相容 OpenAI 的端點只要給 base URL 就能用。這種配置 API 成本為零，資料完全不離開你的電腦。一個提醒：本機模型需要更明確的提示。把任務拆成清楚的步驟，別丟一句高層次的模糊指令。

上架 Chrome 線上應用程式商店了嗎？

已經上架了。從 Chrome 線上應用程式商店一鍵安裝，Chrome 會幫你保持更新。若不想透過商店，本頁的 zip 可以用載入未封裝項目安裝——這種安裝方式升級時要替換資料夾， 然後到 chrome://extensions 的 Flowkite 卡片上按重新整理。完整步驟見快速開始。

哪些資料會離開我的電腦？

頁面結構，以及，只有你開啟視覺功能時，螢幕截圖，用你的金鑰送往你選擇的 LLM 供應商； 資料到了他們那裡就適用他們的政策，所以挑一家你放心的。附帶分析金鑰的建置版本也會向 PostHog 送匿名使用事件，任務開始、完成、失敗或取消，加上代理造訪的每個網域的主機名稱，在 選項 → Analytics 可以關掉；你自己編譯的版本不帶金鑰，所以根本不會執行。 你的設定、任務歷史、API 金鑰和記憶都留在 chrome.storage.local，永不上傳。

支援哪些瀏覽器？

完整支援 Chrome 與 Edge。Firefox 與 Safari 不支援，Flowkite 是建立在 Chrome 自家 API 上的 Manifest V3 擴充功能。其他 Chromium 系瀏覽器如 Brave、Arc、Opera 或許能用，但未經測試。
